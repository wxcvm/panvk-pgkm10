# 受限工作负载日志诊断

`RC3-anbfix3-wsi3` 在同一固定 RC3 / Mesa 源码及 019、020、021 修复上加入 022～025。
它包含工作负载记录和默认关闭的布局、缓存诊断开关，尚未通过实屏验收，不作为正式安装包。

默认不记录日志；临时设置 `debug.mesa.movecert.trace=1` 后，Android logcat 的
`MoveCertVK` 标签记录图像格式、尺寸、层数、采样数、用途，以及渲染通道附件、
子通道和管线的部分标志。每个源文件最多 512 条。记录不含着色器字节、游戏内容，
也不写文件或上传；设备上的日志仅保留在本地诊断目录。

补丁只读取 Vulkan 接口要求有效的字段，避免解引用管线中可能被忽略的可选状态。
Linux 主机代码生成构建保留空日志函数。Android 的输出依赖现有 `liblog` 和 libc。
开启日志可能影响时序，因此不能把诊断版本的表现直接视为稳定性验证通过。

独立工作流 `Build PanVK workload diagnostic` 使用 `diagnostic-build.json`。
在 CI 工作目录临时将该输入复制到现有构建脚本读取的位置，并随产物保存实际输入、
来源、许可和诊断补丁。原实验构建输入和证书模块安装配置不变。

启用前应先在独立进程回归，再使用有恢复脚本的临时游戏测试。测试结束恢复原属性
和原厂驱动，并分别核对 init、Zygote、WebView 命名空间。

## 交换链分配对照

023 添加默认关闭的 `MOVECERT_WSI_CPU` 开关；Android 对应属性为
`debug.mesa.movecert.wsi.cpu=true`，属性名小于 Mesa 的 32 字节缓冲区限制。
它在 gralloc 0 和 gralloc 1 两种用量查询路径请求 CPU 可读的交换链缓冲区，
保留原有 GPU 用量要求，不执行 CPU 读写，也不修改已经分配的图像布局。

该请求可能使厂商分配器选择不压缩的布局，但不能保证；测试必须检查实际的
缓冲区 modifier。它不会关闭硬件合成。接受结果前应同时确认实际加载的驱动、
Vulkan 渲染接口、缓冲区格式、合成方式以及实屏表现。截图或 PixelCopy 正常
不能单独证明实屏正常。此开关仅用于诊断，不默认启用，不打包进正式安装器。

## 原生缓冲区显示边界的缓存对照

024 添加独立的 `MOVECERT_WSI_FLUSH` 开关（Android 属性
`debug.mesa.movecert.wsi.flush=true`），默认关闭。在 CSF 命令缓冲区中，
仅对 Android 原生缓冲区及其别名的 `PRESENT_SRC_KHR` 图像屏障请求现有的
主机域缓存操作：释放到显示时写回 L2/LS，重新获取时清理并失效相关缓存。
普通图像、其他平台的图像及关闭开关时的行为保持原样。

这一对照不更改缓冲区分配格式，也不切换系统合成方式。启用时，每个获取或释放
日志点最多输出一次 `MoveCertWSI` 消息，用于核实该路径被实际调用；不记录图像
内容。必须单独测试，不能同时启用分配对照后将结果归因于缓存处理。它仍是候选
诊断处理，尚未证明是正式修复。

## 厂商 AFBC 数据区对齐对照

025 添加默认关闭的 `MOVECERT_AFBC_ALIGN`（Android 属性
`debug.mesa.movecert.afbc.align=true`）。仅在 Android、GPU 架构 v10、
modifier `0x0800000000000072` 下，把数据区对齐设为 1024 字节；头部对齐、
压缩格式和系统合成方式不变。通过共用布局函数同时调整分配大小和渲染描述符，
避免只移动写入地址导致越界。其他组合及关闭开关时使用原有计算。

独立程序创建 1080×2412、usage 0xb00 的测试缓冲区并清为固定颜色，等待 GPU
栅栏后读取其自身 DMA 缓冲区：PanVK 首块偏移为 `0x28200`，原厂为 `0x28400`，
其余示例头字段一致。此差异与公开 Mali Gralloc 的 1024 字节对齐、
[MediaTek 上游 AFBC 对齐问题讨论](https://lists.openwall.net/linux-kernel/2026/02/02/193)
相符，但不能仅凭内存布局对照认定实屏缺陷已修复。

启用后 `MoveCertAFBC` 日志确认对齐路径生效。先重新检查自建缓冲区的头部和
基础回归，再保持原压缩格式与硬件合成进行实屏验证；分配及缓存诊断开关关闭。
本补丁仍只进入诊断构建，不默认启用，也不进入正式安装器。

## WSI4：P010 查询顺序与微信同步诊断

026 将标准 mapper 元数据查询提前到旧 HAL 格式转换之前，解决 P010 被旧格式表
拒绝而根本无法进入现代 mapper 的控制流问题。独立 mapper 查询已确认本机能返回
线性 P010 和 AFBC 压缩 YUV 的不同布局。完整驱动的属性查询、导入和采样仍需验证；
该改动不猜测格式、平面偏移或 FD，也不表示已支持所有压缩 YUV 导入。

027 增加默认关闭的 `MOVECERT_SYNC_TRACE`（Android 属性
`debug.mesa.movecert.sync.trace=true`），每进程最多输出 2048 条 `MoveCertSync`
生命周期记录。记录对象标识、状态、等待回调及目标序号，用于区分 RESET 状态等待、
正在执行的等待回调和信号量复用；不修改同步语义、不缩短等待、不伪造完成。
诊断日志保持本地，性能对照时必须关闭此开关。

这两项仅进入 `RC3-anbfix3-wsi4` 诊断构建，现有 WSI3 安装包不自动升级或启用。

WSI4 的独立验证结果：线性 P010 属性查询、图像导入和视图创建成功，但缺少
`SAMPLED_IMAGE` 格式能力，尚不能宣称可用于采样；压缩 `YU10` 格式仍未支持。
基础二值信号量、临时 SYNC_FD 导入、时间线等待，以及 AFBC/原生缓冲区回归通过。
这些结果不等于微信兼容性通过。

## WSI5：关联队列依赖

WSI4 在确认加载的微信进程中仍复现卡死：栅栏等待完成后，渲染线程等待另一枚
自创建以来一直处于 RESET 状态的同步对象，未见该对象的 pending/signal 事件。
此前“页面正常”的一轮中应用已被重新启动并回到原厂驱动，因此不能作为通过证据。
测试结束后已恢复原厂环境，全局替换保持关闭。

028 沿用默认关闭的 `MOVECERT_SYNC_TRACE`，额外记录最多 2048 条 `MoveCertQueue`
事件，把信号量、临时/永久载荷、提交批次和队列边界关联起来。它仅增加诊断，
不改变等待或提交顺序。WSI5 尚未证明解决卡死；性能测试须关闭所有诊断输出。

WSI5 实机回归：六组独立同步测试、AFBC 对齐与原生缓冲区像素/FD 回归通过。
微信仍卡住，日志首次关联到同一信号量的两次等待：第一次使用已发信号的临时
载荷，且提交完成；随后另一批提交使用其从未收到信号的永久载荷并阻塞。
两次等待之间未记录到这枚信号量的 signal。尚需确认两次提交的调用来源，
不能据此直接归因给微信或通过伪造信号规避。

## WSI6：早期提交调用栈

029 在同一默认关闭的诊断开关下，给前 64 条队列事件中的信号量依赖增加
最多 24 层调用地址，用于区分应用、系统 Vulkan 层与驱动内部提交。不记录
栈内存或页面内容，不改同步语义。应用验证后应立即关闭诊断；性能结果不能
来自开启调用栈输出的测试。本版本仍不用于全局安装。
