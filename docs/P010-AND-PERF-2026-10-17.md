# P010 / YU10 导入路径与驱动微基准（2026-10-17）

## 一、P010 路径状态（补丁 026 的实测结论）

用仓库内 `tools/p010-probe/` 的独立探针直接加载 wsi7 ICD，在 root 进程中创建
1272×2772 的 AHardwareBuffer，比较 OEM 与 wsi7：

| AHB 格式 / usage | OEM | wsi7 |
|---|---|---|
| RGBA8888 / `0x100` | 属性查询成功 | 成功 |
| **P010 / `0x100`（线性）** | 成功 | **成功**：属性、`CreateImage`、`AllocateMemory`、`BindImageMemory`、YCbCr conversion、`CreateImageView` 全部 `VK_SUCCESS` |
| **P010 / `0x400900`（压缩 YU10，SF tombstone 同款）** | 成功 | **仍失败 `VK_ERROR_INVALID_EXTERNAL_HANDLE`** |

结论：

1. 补丁 026（mapper 前置查询）**确实修复了线性 P010 的导入链路**，与 wsi4 起的
   历史记录一致（当时 case1 通过、case2 失败）；
2. SurfaceFlinger 早前 abort 的缓冲区是 **format 54 + usage 0x400900 + stride 1280 +
   1272×2772**，对应压缩 YU10（fourcc `0x30315559`，modifier `0x0800000000000041`），
   该格式目前仍不被 PanVK 接受，报 `Unsupported external DRM format`；
3. 因此 **`debug.renderengine.backend=skiavk`（SF 用 Vulkan 合成）+ 10-bit 压缩视频**
   仍会触发同一类纹理创建失败。当前推荐配置是 **SF 保持 `skiagl`**（OEM GLES 合成），
   此时不受该缺陷影响；全局启用 PanVK 已由第 2 轮验证可通过。

后续若要支持 skiavk 合成，需要为 YU10+AFBC modifier 增加外部格式映射与 YCbCr 描述，
属于驱动源码改动，尚未实现。

## 二、驱动微基准（提交开销 / 清屏吞吐）

`tools/bench/gpu-vk-bench.c`，3 轮交替取中位数：

| 指标 | OEM | wsi7 | 变化 |
|---|---|---|---|
| 512×512 每次提交 | 0.562 ms | 0.419 ms | −26% |
| 512×512 清屏吞吐 | 1.92 GB/s | 2.50 GB/s | +30% |
| 2048×2048 每次提交 | 0.781 ms | 0.536 ms | −31% |
| 2048×2048 清屏吞吐 | 21.48 GB/s | 31.30 GB/s | +46% |

解释：wsi7 在这两类基础工作负载上没有性能回退，提交延迟与 GPU 写带宽均优于 OEM
驱动。这是驱动层数据，不等于真实应用帧率；应用层指标（冷启动、游戏帧率）另行测量。

## 三、本轮设备环境

- 手机当前为**原厂驱动**状态（测试模块 `panvk-wsi7-global-test` 已 `disable`）；
- 探针与基准均为进程内直接加载，未改动任何系统挂载/属性。
